# Arid 1.1.0 — Adoption & Integration

**Released:** August 16, 2026

Arid 1.1.0 makes the stable 1.0 detector easier to adopt in real projects and easier to integrate into CI without changing what Arid considers duplicate code.

The release adds richer output, baseline-based incremental adoption, and first-class pre-commit integration while preserving the existing duplicate semantics and JSON compatibility.

## Highlights

- Add explicit output selection with `--format text|json|markdown|sarif`.
- Add Markdown output for human-readable reports.
- Add SARIF 2.1.0 output for CI and code-scanning integrations.
- Add colored text output with `--color auto|always|never` and standard terminal color environment support.
- Add baseline-based incremental adoption so existing duplicate debt can be accepted while new debt still fails the scan.
- Add official pre-commit integration that preserves whole-project duplicate detection.
- Keep `--json` as a compatible shorthand for JSON output.

## Baseline-based adoption

Create a baseline for existing duplicate debt:

```bash
arid . --write-baseline arid-baseline.json
```

Then enforce it explicitly:

```bash
arid . --baseline arid-baseline.json
```

A baseline can also be configured in `[tool.arid]` so normal project scans enforce it automatically.

## Output formats

```bash
arid . --format text
arid . --format json
arid . --format markdown
arid . --format sarif
```

Text remains the default format.

## Compatibility

Arid 1.1.0 is backward compatible with 1.0. Existing duplicate-detection semantics, source locations, `DUP001`, JSON behavior, configuration, and exit-status behavior remain intact.

Existing workflows that use `arid .` or `arid . --json` do not need to change.

## Install or upgrade

With `uv`:

```bash
uv tool upgrade arid
```

With `pip`:

```bash
python -m pip install --upgrade arid
```
